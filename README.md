# Telegram Parser + Sender

Парсер на Telethon читает новые сообщения исходного чата и публикует JSON в RabbitMQ.
Бот на aiogram отправляет текст с исходным оформлением во все чаты, куда его добавил
владелец с `ADMIN_ID`. Предпросмотр ссылок отключён.
Все сервисы запускаются одним Docker Compose; настройки находятся в корневом `.env`.

## Первый запуск на сервере

Нужны Docker Engine с Compose v2 и исходники проекта. Команды выполняются из корня проекта.

1. Создайте `.env` из `.env.example`, если своего файла ещё нет:

   ```bash
   cp .env.example .env
   chmod 600 .env
   ```

2. Заполните значения:

   | Переменная | Назначение |
   | --- | --- |
   | `API_ID`, `API_HASH` | Данные приложения Telegram с https://my.telegram.org |
   | `CHAT_ID` | Username или числовой ID исходного чата; аккаунт парсера должен иметь к нему доступ |
   | `BOT_TOKEN` | Токен бота от @BotFather |
   | `ADMIN_ID` | Числовой Telegram ID единственного владельца бота |
   | `RABBITMQ_USER`, `RABBITMQ_PASSWORD` | Учётная запись RabbitMQ; используйте пользователя, отличного от `guest` |
   | `RABBITMQ_QUEUE` | Имя очереди, по умолчанию `telegram_posts` |
   | `TELEGRAM_PROXY_HOST`, `TELEGRAM_PROXY_PORT` | Необязательный SOCKS5-прокси парсера; пустой host означает прямое подключение |

   Пароль RabbitMQ можно сгенерировать командой `openssl rand -hex 24`.
   Используйте буквы/цифры в логине и hex-пароль: Compose вставляет их в AMQP URL.
   Адрес брокера внутри контейнеров — `rabbitmq:5672`; Compose задаёт его автоматически.
   `127.0.0.1` внутри контейнера — сам контейнер, поэтому прежний локальный прокси
   `127.0.0.1:2080` для серверного запуска не подходит.

3. Проверьте конфигурацию и соберите образы:

   ```bash
   docker compose config --quiet
   docker compose build
   docker compose up -d --wait rabbitmq
   ```

4. Один раз авторизуйте аккаунт парсера. Команда интерактивно запросит телефон,
   код Telegram и пароль двухфакторной аутентификации, если он включён:

   ```bash
   docker compose run --rm --no-deps parser python -m src.auth
   ```

### Вход по QR-коду (удобно на VPS)

Альтернатива интерактивному входу без ввода телефона и кода из SMS:

```bash
docker compose build parser
docker compose run --rm --no-deps parser python -m src.qr_auth
```

В журналах команды печатается ASCII-QR-код и ссылка `tg://login?token=...`,
а картинка сохраняется в volume: `parser_data/qr.png` (внутри контейнера —
`/data/qr.png`). Откройте Telegram на телефоне: **Настройки → Устройства →
Подключить устройство** — и наведите камеру на QR. Ссылку можно открыть и в
Telegram Desktop на компьютере: он предложит подтвердить вход.

Если QR истёк, команда автоматически сгенерирует новый. При включённой 2FA
передайте пароль через переменную окружения:

```bash
TELEGRAM_2FA_PASSWORD='пароль' docker compose run --rm --no-deps parser python -m src.qr_auth
```

Сессия сохраняется в volume `parser_data`, поэтому пересборка и перезапуск
контейнеров повторной авторизации не требуют. Забрать PNG с QR на хост:

```bash
docker compose cp parser:/data/qr.png ./qr.png
```
   Сессия сохранится в том `parser_data`. Обычный сервис не запрашивает код:
   без готовой сессии он завершится с инструкцией пройти авторизацию.

5. Запустите проект:

   ```bash
   docker compose up -d
   docker compose ps
   docker compose logs -f --tail=100 parser sender
   ```

6. Добавьте бота в нужные группы или каналы от аккаунта с `ADMIN_ID`.
   Разрешите отправку сообщений, в канале — право администратора на публикацию.
   Если бота добавит другой пользователь, бот выйдет. Для ранее добавленной группы
   владелец может отправить `/register`; в канале удалите и снова добавьте бота.

## Данные и обновление

Compose создаёт постоянные тома:

- `rabbitmq_data` — очередь и состояние RabbitMQ;
- `parser_data` — Telegram-сессия `/data/parser.session`;
- `sender_data` — список чатов `/data/chats.json`.

Они сохраняются при пересоздании контейнеров и `docker compose down`.
Команда `docker compose down -v` удаляет эти данные. Сохраняйте резервные копии томов
и `.env` перед переносом на другой сервер. Образы не содержат `.env`, сессий и списка чатов.

Для обновления загрузите новую версию исходников и выполните:

```bash
docker compose up -d --build
```

Для остановки: `docker compose stop`. Сервисы автоматически запускаются после
перезапуска Docker, если не были остановлены вручную. Логи ограничены по размеру.
Приложения работают без root; parser и sender ждут готовности RabbitMQ.
Запускайте один экземпляр каждого приложения: Telegram-сессию и JSON-файл нельзя
совместно использовать несколькими экземплярами.

Повторную авторизацию выполняйте после `docker compose stop parser`, затем
запускайте `docker compose up -d parser`.

## Перенос уже существующих локальных данных

Если в проекте есть рабочий `parser/parser.session`, его можно перенести вместо
повторной авторизации. Сначала остановите локальный парсер и контейнер parser:

```bash
docker compose run --rm -T --no-deps parser sh -c 'cat > /data/parser.session' < parser/parser.session
```

Аналогично для существующего `sender/chats.json`, при остановленном sender:

```bash
docker compose run --rm -T --no-deps sender sh -c 'cat > /data/chats.json' < sender/chats.json
```

Выполняйте эти команды только для существующих файлов, до запуска сервисов.
Учётные данные `RABBITMQ_DEFAULT_USER/PASS` применяются только при создании нового
хранилища RabbitMQ. Для уже используемого тома сначала настройте в брокере пользователя
и права на vhost `/`, соответствующие `.env`; смена переменных не меняет пароль в существующей базе.
Не удаляйте старый том с очередями для смены учётных данных.

## Сеть и ограничения доставки

Порты RabbitMQ опубликованы только на loopback сервера: AMQP `127.0.0.1:5673`,
панель управления `127.0.0.1:15673`. Для панели со своего компьютера используйте SSH-туннель:

```bash
ssh -L 15673:127.0.0.1:15673 user@server
```

Затем откройте http://localhost:15673 и войдите с учётными данными из `.env`.
Входящие публичные порты приложениям не нужны: Telegram используется через исходящие подключения.

Парсер читает только новые сообщения во время работы; история простоя не загружается.
Медиа не пересылаются. Sender отправляет одно текстовое сообщение на элемент очереди
(лимит Telegram — 4096 символов). RabbitMQ подтверждается после рассылки; при сбое
посреди рассылки возможны дубли. Ошибка отправки в один чат приостанавливает очередь:
восстановите права бота либо удалите его из этого чата при работающем sender.
